# Трекер привычек

---

Сервис для формирования и отслеживания привычек с интеграцией Telegram‑рассылок, валидацией правил и API для фронтенда.
Позволяет пользователям создавать полезные и приятные привычки, настраивать напоминания и просматривать публичные примеры.

---

## Основной функционал

### Привычки
- Создание привычек по шаблону: «я буду ```[ДЕЙСТВИЕ]``` в ```[ВРЕМЯ]``` в ```[МЕСТО]```».
- Разделение на:
  - полезные привычки (основные действия с вознаграждением); 
  - приятные привычки (вознаграждение за выполнение полезных); 
  - связанные привычки (приятные привычки, привязанные к полезным).

- Валидация правил:
  - Нельзя одновременно указать вознаграждение и связанную привычку. 
  - Время выполнения не более 120 сек. 
  - В связанные привычки попадают только приятные. 
  - У приятных привычек нет вознаграждения или связей. 
  - Периодичность: 1–7 дней (не реже раза в неделю). 
  - Публичность: возможность публиковать привычки для общего просмотра.

### Пользователи
- Регистрация и авторизация.
- Доступ к CRUD-операциям только для своих привычек.
- Просмотр публичных привычек без права редактирования.

### Уведомления
- Рассылки напоминаний через Telegram.
- Отложенные задачи для своевременных уведомлений.

### API и интеграция
- REST‑эндпоинты для фронтенда.
- Пагинация списков (5 привычек на страницу).
- CORS‑настройка для безопасного подключения фронтенда.
- Автоматическая документация API.

## Модель данных

###  ```Habit``` (Привычка)

- ```user``` — создатель привычки (связь с пользователем).
- ```place``` — место выполнения.
- ```time``` — время выполнения.
- ```action``` — описание действия.
- ```is_pleasant``` — флаг: приятная привычка?
- ```related_habit``` — связанная приятная привычка (только для полезных).
- ```periodicity``` — периодичность (1–7 дней).
- ```reward``` — вознаграждение (только если нет related_habit).
- ```execution_time``` — время выполнения (не более 120 сек).
- ```is_public``` — публичная видимость.
- ```created_at``` — дата создания.

###  Ограничения модели

- Валидаторы проверяют взаимоисключающие поля (```reward``` vs ```related_habit```).
- Каскадные проверки для связанных привычек.

## Интеграция с Telegram

### 1. Бот для уведомлений:

- Отправляет напоминания о привычках по расписанию.
- Использует ```tg_chat_id``` пользователя из профиля.

### 2. Механизм отложенных задач:

- Celery для планирования уведомлений.
- Проверка активных привычек и времени отправки.

---

## Безопасность

 - JWT‑аутентификация для API.
 - CORS настроен для разрешённых фронтенд‑доменов.
 - Права доступа:
   - Пользователь видит только свои привычки.
   - Публичные привычки доступны для чтения всем.

## Установка и запуск на локальной машине
### 1. Клонировать репозиторий:
```
git clone https://github.com/AzatAlfredovich/habit_tracker.git
```
### 2. Создать .env по шаблону:
`.env.sample`
### 3. Установить зависимости:
`pip install -r requirements.txt`
### 4. Применить миграции:
`python manage.py migrate`
### 5. Создать группу менеджеров:
`python manage.py create_manager_group`
### 6. Запустить сервер:
`python manage.py runserver`
### 7. Настроить Telegram-бота:
`Указать токен в .env`

## Установка и запуск на виртуальной машине:
### 1. Настройте виртуальную машину, актуализируйте ее зависимости и доступность:
```
sudo apt update
sudo apt upgrade
sudo ufw status
sudo ufw enable
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw allow 22/tcp
```
### 2. Подключитесь к ВМ по SSH-ключу и клонируйте репозиторий (в первый раз):
```
git clone https://github.com/AzatAlfredovich/habit_tracker.git
```
В остальных случая рекомендуется выполнять ```git pull``` при изменениях в коде на Git!
### 3. Внесите данные и корректировки в .env файл (для разворачивания и деплоя)
### 4. Создайте Dockerfile
### 5. Создайте ```docker-compose.yml``` для управления контейнерами
### 6. Создайте директорию ```.github/workflows``` с ```example_for_ci.yml``` для описания Git CI/CD пайплайна
### 7. Рекомендуется создать .env файл на ВМ в корневой директории с целью корректной работы БД (по желанию)
```
nano .env
```
### 8. Выполните `commit and push` изменений и дождитесь отработки GitAction: в случае успешного прохождения - сервер запустится и будет доступен по адресу:
`http://130.193.59.148:8000`
- Примечание - IP-адрес может быть и другим!
